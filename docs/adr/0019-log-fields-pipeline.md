# ADR-0019: Which fields a log has: a pipeline, a noise filter by type, and a map measured from a run

- **Status:** Accepted
- **Date:** 2026-10-25

## Context

Graylog turns every property of a log into a field; fields that nobody searches for (the TCP connection id, the endpoint ids ASP.NET puts on every log, the span ids) bury the useful ones, and an object logged with `{@Object}`
would create fields without end. We also noticed that a field list kept by hand drifts from reality.

## Decision

- **The pipeline** (`BaseSerilog.Create`), for every log: scopes and message arguments become properties; the enrichers add `Solution`, `Assembly`, `Version`, `LoggerName`, `Facility`, `LogType` and `MessageType`; then
  **`NoiseEnricher` removes** what a type must not have; then the product's own enrichers run (they can add or remove more); and for the persistent sink **`FieldGuardSink`** shapes the values.
- **`NoiseEnricher`:** `ConnectionId` from every log; the fields of who asked (`UserId`, `UserRoles`, `ClientChannel`, `ClientVersion`, `ClientLat`, `ClientLong`) from `FrameworkLog` and `PlatformLog` (they belong to the logs of a request, of
  a message and of the application); the endpoint, span and request fields of ASP.NET and the tracing (`ActionId`, `ActionName`, `ParentId`, `RequestId`, `RequestPath`, `SpanId`) from `AppLog` and `SharedLog` (the
  `HttpRequest` and `HttpResponse` of the same request have them). The lists are in the code.
- **`FieldGuardSink`:** an object, a dictionary or a list becomes **one field of its name holding its JSON**, text is cut at `PersistentLogger:MaxPersistentFieldLength` (16384, above the 8192 of a body or a reason, so those are not cut twice,
  and a cut is marked `...(+N)`), the message is written as people read it (no quotes around texts), and `EventId` and `MessageDetails` (a placeholder that only builds message text) are not fields.
- **Decisions on single fields:** `RequestPath` (not `Path`) everywhere; no `Scheme`, no `ContentLength`, no `EventId_Id`/`EventId_Name`, no `Details` field (its text is in the message); `UserId` and `UserRoles` only on the request,
  response, message and application logs; `Facility` is a top-level field (the event name, or `BeginFacility`).
- **To add a field to every log, or to remove one, a product writes an enricher** in the `configure` of `AddBaseSerilog` (it runs after `NoiseEnricher`, so `RemovePropertyIfPresent` can remove what the framework leaves). What the
  framework must never put on a type goes in `NoiseEnricher`.
- **The field map is measured, not declared:** `docs/GraylogFields.md` is generated by `scripts/graylog-fields/generate.py <Version>` from the logs of one real run of the samples in Graylog (`●` every log, `◐` some, empty never, `?` no log of that
  type in the run). Regenerate it after a change to the fields; the Graylog credentials come from the environment and are never written to a file.

## Consequences

- The lists in `NoiseEnricher` are code, not configuration: a product cannot change them without code (it adds an enricher). Configurable `RemoveFields`/`AddFields` per type is an option if needed.
- A field that appears because a library started to add it shows in the map in the column of the type that carries it; look at the map after a package change.
- Nothing enforces the map; it documents a measurement. A test that fixes the allowed fields per type would, and is not written.
